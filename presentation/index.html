Why AWS Amplify Hosting?

Config · CD

amplify.yml — the build spec

Lives at the repo root. Amplify runs it on every push to a connected branch.

version: 1
frontend:
  phases:
    preBuild:
      commands:
        - npm ci            # reproducible install
    build:
      commands:
        - npm run build     # Vite → dist/
  artifacts:
    baseDirectory: dist   # what to deploy
    files:
      - '**/*'
  cache:
    paths:
      - node_modules/**/* # faster next build
Config · CI

.github/workflows/ci.yml

Runs on every push and PR to main. Green checks gate the merge.

name: CI
on:
  push: { branches: [main] }
  pull_request: { branches: [main] }
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm run lint
      - run: npm test
      - run: npm run build
Mental model

Who does what?

Continuous Integration

GitHub Actions

  • Runs on every push & PR
  • Lint → Test → Build
  • Fails the check if code is broken
  • No cloud credentials needed
Continuous Delivery

AWS Amplify

  • Watches the connected branch
  • Builds via amplify.yml
  • Deploys to CDN + HTTPS
  • Spins up PR preview URLs

Want it all in one place? Actions can trigger the deploy too (ci-deploy.yml via aws amplify start-job + OIDC) — at the cost of preview deploys.

Setup · one time

Connecting Amplify to GitHub

  • 1 Push the repo to GitHub
  • 2 AWS Console → Amplify → Create new app → Deploy with GitHub
  • 3 Authorize AWS ↔ GitHub, pick the repo + main branch
  • 4 Amplify auto-detects amplify.yml — confirm
  • 5 First build runs (~1–2 min) → live at *.amplifyapp.com

Done. Every future push to main auto-deploys. Add a custom domain in App settings (Amplify manages the cert).

Cost & gotchas

Cost

  • Free tier: build minutes + hosting/GB
  • Then pay-per build-minute & per-GB served/stored
  • GitHub Actions: free minutes on public repos

Gotchas

  • SPA routing → add a 200 (Rewrite) to /index.html
  • Env vars set in Amplify console, not committed
  • Match Node version (build vs CI)
  • baseDirectory must match build output (dist)
Context

Alternatives worth knowing

Other hosts

  • Vercel / Netlify — same Git-push UX, less AWS
  • Cloudflare Pages — edge-first
  • S3 + CloudFront — DIY, most control

Other CI/CD

  • Amplify-only — put tests in amplify.yml preBuild
  • Actions does everything — build + start-job
  • AWS CodePipeline — heavier, all-AWS

Our pick: Actions for CI + Amplify Git integration for CD — simplest path to previews & rollbacks.

Wrap up

Takeaways

  • Amplify turns git push into a deployed, HTTPS, CDN-hosted site
  • amplify.yml = the build recipe; that's the whole config
  • GitHub Actions guards quality before merge
  • PR previews + one-click rollback come for free
  • Two config files, and you have real CI/CD
